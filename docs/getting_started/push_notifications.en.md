# Push notifications

The Agromate server watches the metrics published by your Agrosmarts and sends a **push notification** to your phone
when something needs your attention: the water tank is running low or the temperature is out of the range you chose
for the plant. Notifications are delivered through **Firebase Cloud Messaging** (FCM), so both the server and the app
need to be connected to a Firebase project.

Notifications are optional: without Firebase the server and the app keep working, you just don't receive the alerts.

This guide assumes you already have a working server, as described in [First steps](/docs?article=first_steps).

## Alerts

| Alert                    | Sent when                                                                              | Example                                                                                  |
| ------------------------ | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **Water reserve**        | The [water level sensor](/docs?article=building_agrosmart) reports the tank at reserve | _Greenhouse 1: water reserve_ The water tank is almost empty, refill it to keep...       |
| **Temperature too low**  | The temperature is below the minimum of the **Temperature Range** of the Agrosmart     | _Greenhouse 1: temperature too low_ The temperature is 12.5°C, below the minimum of 15°C |
| **Temperature too high** | The temperature is above the maximum of the **Temperature Range** of the Agrosmart     | _Greenhouse 1: temperature too high_ The temperature is 36°C, above the maximum of 30°C  |

The notification title starts with the name you gave to the Agrosmart, or with its MAC address if it has no name. The
temperature limits are the ones set in the [plant care settings](/docs?article=overview) of each Agrosmart, so you can
change them at any time from the app.

A few rules avoid flooding your phone:

- the same alert of the same Agrosmart is sent **at most once every 6 hours** (configurable with
  `NOTIFICATION_COOLDOWN_MINUTES`). The cooldown is kept in memory, so it starts over when the server restarts;
- the owner and the settings of each Agrosmart are cached for **15 minutes** (`AGROSMART_CACHE_TTL_MS`): after changing
  the temperature range in the app, the new limits may take up to 15 minutes to be used for the alerts;
- the alerts are sent to **every phone** where the owner of the Agrosmart is logged in.

> [!NOTE]
> The text of the notifications is generated by the server and is in English only for now.

## How it works

1. After login, the app registers itself to FCM and gets its **Firebase Installation ID** (FID), an identifier of that
   app installation. It sends the FID to the server (`POST /fcm_installation`), which links it to your account.
2. The Agrosmart publishes its metrics on the `agrosmart/metrics` MQTT topic, as usual.
3. A worker thread of the server, subscribed to `agrosmart/metrics`, compares every metric with the settings of the
   Agrosmart and decides whether an alert must be sent.
4. The server sends the alert to FCM, authenticating with a Firebase **service account**, addressed to all the FIDs of
   the owner.
5. FCM delivers the notification to the phones.

When you log out from the **Profile** tab, the app removes its FID from the server (`DELETE /fcm_installation`), so
that phone stops receiving your alerts. FIDs that FCM reports as no longer valid (for example because the app was
uninstalled) are removed automatically, and deleting your account removes all of them.

> [!IMPORTANT]
> The app and the server must use the **same Firebase project**: a service account can send notifications only to the
> app installations of its own project. If you host your own server, you have to create your own Firebase project and
> build the app with it, as described below.

## 1. Creating the Firebase project

1. Open the [Firebase console](https://console.firebase.google.com/) and sign in with a Google account.
2. Click **Create a project** (or **Add project**), choose a name, e.g. `agromate`, and complete the wizard. Google
   Analytics is not needed and can be disabled.
3. Note down the **project ID** shown in **Project settings → General** (e.g. `agromate-1a2b3`): you need it to
   configure the app.
4. In **Project settings → Cloud Messaging**, check that **Firebase Cloud Messaging API (V1)** is _Enabled_. If it is
   not, open the menu next to it and enable it from the Google Cloud console.

The free **Spark** plan is enough: Cloud Messaging has no cost.

## 2. Configuring the server

### Generating the service account key

The server authenticates to FCM with the private key of a service account:

1. In the Firebase console, open **Project settings → Service accounts**.
2. With **Firebase Admin SDK** selected, click **Generate new private key** and confirm. A JSON file is downloaded.
3. Rename it to `firebase-service-account.json`.

> [!CAUTION]
> This file contains a private key with administrative access to your Firebase project. Don't share it and don't
> commit it: the server repository already ignores `*service-account*.json`. **Never** put it in the server `public/`
> folder, whose content is served to anyone without authentication.

The server always reads the key from `./firebase-service-account.json`, a path **relative to the directory it is
started from**. If the file is missing, the notification worker can't start (see **Troubleshooting** below).

### Environment variables

All the notification variables are optional:

| Variable                        | Default           | Description                                                                                    |
| ------------------------------- | ----------------- | ---------------------------------------------------------------------------------------------- |
| `NOTIFICATION_COOLDOWN_MINUTES` | `360`             | Minimum time between two notifications of the same alert for the same Agrosmart                |
| `AGROSMART_CACHE_TTL_MS`        | `900000` (15 min) | How long the owner and the settings of an Agrosmart are cached by the worker                   |
| `ALERT_DRY_RUN`                 | unset             | When `true`, Firebase is not used at all: the alerts are only written to the log (for testing) |

### Server configuration

Put the key in the `server` folder created by the [Docker Compose setup](/docs?article=first_steps), next to `data`
and `public`, and mount it **read-only** in the container at `/app/firebase-service-account.json` (`/app` is the
working directory of the image):

```yaml
agromate-server:
  # ...
  environment: NOTIFICATION_COOLDOWN_MINUTES=360
    AGROSMART_CACHE_TTL_MS=900000
    ALERT_DRY_RUN=false
  volumes:
    - ./server/data:/app/data
    - ./server/public:/app/public
    - ./server/firebase-service-account.json:/app/firebase-service-account.json:ro
```

The server runs as the unprivileged `agromate` user inside the container, so the file must be readable by it:

```bash
chmod 644 server/firebase-service-account.json
```

Then recreate the container:

```bash
docker compose up -d agromate-server
```

### Checking the server

After the restart, the server log should contain:

```text
Connected to MQTT Broker, subscribing to agrosmart/metrics
Subscribed to agrosmart/metrics
```

## 3. Configuring the mobile app

The app already contains all the code to receive notifications: you only need to connect it to **your** Firebase
project and build it.

### Requirements

- The [Flutter SDK](https://docs.flutter.dev/get-started/install) and the
  [app source code](https://github.com/agromate-devs/new_mobile_app)
- The [Firebase CLI](https://firebase.google.com/docs/cli), logged in with the account that owns the project:

  ```bash
  npm install -g firebase-tools
  firebase login
  ```

- The FlutterFire CLI:

  ```bash
  dart pub global activate flutterfire_cli
  ```

### Connecting the app to Firebase

From the app folder, run:

```bash
flutterfire configure --project=<your-project-id>
```

Select the platforms you want to build (**android**, and **ios** if you need it). FlutterFire registers the apps in
your Firebase project (on Android with the package name `com.example.agromate_mobile_app`) and generates:

| File                                  | Content                                                   |
| ------------------------------------- | --------------------------------------------------------- |
| `lib/firebase_options.dart`           | Firebase options used by `Firebase.initializeApp()`       |
| `android/app/google-services.json`    | Android configuration, read by the Google Services plugin |
| `ios/Runner/GoogleService-Info.plist` | iOS configuration (only if you selected iOS)              |
| `firebase.json`                       | FlutterFire settings, used when running `configure` again |

If these files already exist they belong to another Firebase project: let `flutterfire configure` overwrite them,
otherwise the app registers to a project your server can't send to. Run it again whenever you change the Android
`applicationId` or add a platform.

> [!NOTE]
> Unlike the service account key, these files are not secret: they only identify the Firebase project and don't allow
> sending notifications.

Check that `API_URL` in the app `.env` file points to your server, then build and run the app:

```bash
flutter pub get
flutter run
```

The project already includes the rest of the setup, you don't need to change it:

- the `firebase_core`, `firebase_messaging` and `flutter_local_notifications` dependencies;
- the `com.google.gms.google-services` Gradle plugin and the core library desugaring required by
  `flutter_local_notifications`;
- in `AndroidManifest.xml`, `firebase_messaging_installation_id_enabled` set to `true`, which makes the app identify
  itself with the FID (the server sends the notifications to FIDs, not to registration tokens), and
  `default_notification_channel_id` set to `agromate_notifications`.

### Android

After the first login the app asks for the permission to show notifications (Android 13 and later). If you deny it,
the app is still registered but the notifications are not shown: enable them from the notification settings of the app
in the system **Settings**.

Notifications use the **Agromate notifications** channel. When the app is in background or closed they are shown by
the system, when it is in foreground the app shows them itself.

### iOS

> [!WARNING]
> iOS notifications are not configured in the repository yet and have not been tested. The steps below are the
> standard ones required by FCM on iOS.

1. In your [Apple Developer account](https://developer.apple.com/account/resources/authkeys/list) create an **APNs
   authentication key** (`.p8`) and note down its **Key ID** and your **Team ID**.
2. In the Firebase console, open **Project settings → Cloud Messaging → Apple app configuration** and upload the key
   with the Key ID and Team ID.
3. Run `flutterfire configure` selecting **ios**.
4. Open `ios/Runner.xcworkspace` in Xcode and, in **Signing & Capabilities** of the `Runner` target, add the **Push
   Notifications** capability and **Background Modes** with **Remote notifications** checked.
5. Run the app on a real device and accept the notification permission after login.

> [!NOTE]
> Notifications are not available in the web version of the app.

## 4. Testing

1. Start the server and check the log lines shown in **Checking the server**.
2. Log in to the app and accept the notification permission. The server log shows `FID registered`.
3. Trigger an alert. The easiest one is the temperature: in the settings of an Agrosmart, set a **Temperature Range**
   whose maximum is lower than the current temperature, save, and **restart the server** to clear the 15 minutes cache
   and the cooldown. Within one metric publish interval the server log shows:

   ```text
   Alert temperature_high for A1B2C3D4E5F6 sent to mario: 1/1 delivered
   ```

   and the notification appears on the phone. Remember to restore the temperature range afterwards.

You can also lower the water in the tank below the level sensor to test the **water reserve** alert.

### Dry run

To check the alert rules without Firebase, for example while developing, start the server with `ALERT_DRY_RUN=true`.
The service account is not read, a warning at startup says that notifications will only be logged, and every alert
that would be sent is written to the log instead:

```text
[dry run] Alert water_reserve for A1B2C3D4E5F6 to mario (1 FIDs): The water tank is almost empty, refill it to keep irrigating your plant.
```

## Troubleshooting

The notification worker writes its messages in the server log with `module: "metrics-notifier"`.

| Symptom                                                                  | Likely cause                                                                                                                                                              |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Metrics notifier worker exited with code 1, restarting in 5s` in a loop | `firebase-service-account.json` is missing or unreadable in the working directory of the server (`/app` with Docker): check the path, the volume and the file permissions |
| `Subscribe to agrosmart/metrics denied by broker`                        | The `api_server` role can't subscribe to the metrics: add the ACLs shown in **MQTT permissions**                                                                          |
| No `FID registered` after login                                          | Wrong `API_URL` in the app `.env`, or the app was built without a valid Firebase configuration (look for `Error during FCM registration` in the Flutter console)          |
| `Alert ... not sent: user ... has no FID` (debug log)                    | The owner of the Agrosmart is not logged in on any phone, or the FID registration failed                                                                                  |
| `FCM errors for ...: messaging/mismatched-credential: ...`               | The service account belongs to a different Firebase project than the app: run `flutterfire configure` with the project of the key, or generate the key in the app project |
| `FCM errors for ...: messaging/third-party-auth-error: ...` (iOS)        | The APNs key is missing or wrong in the Firebase project                                                                                                                  |
| `1/1 delivered` in the log but nothing on the phone                      | Notification permission denied, _Do not disturb_ active or the **Agromate notifications** channel disabled in the system settings                                         |
| The app gets a `409` when registering the FID                            | The FID of the phone is still linked to another account, e.g. after a session expired without logging out: clear the app data or reinstall the app to get a new FID       |
| An alert arrives once and then no more                                   | Expected: the same alert is repeated only after the cooldown (6 hours by default, `NOTIFICATION_COOLDOWN_MINUTES`)                                                        |
| A new temperature range is ignored                                       | The settings are cached for up to 15 minutes (`AGROSMART_CACHE_TTL_MS`): wait or restart the server                                                                       |
